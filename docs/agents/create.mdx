## Just describe it

The **Agents** page opens on a prompt box. Say what you want in a sentence and Activepieces writes the instructions, picks the tools, and drops you into the finished agent.

<Prompt description="An agent that triages inbound support" icon="sparkles" actions={["copy"]}>
Read new support emails, work out how urgent each one is, reply to the simple ones, and post anything that needs a human into our Slack channel.
</Prompt>

You need an [AI provider connected](/admin-guide/guides/setup-ai-providers) first. If none is set up, the page says so and links you there.

<Tip>
Not sure what to ask for? The page suggests a few starting points, like **Triage support tickets** or **Research a company**. Clicking one builds it immediately, and you can edit everything afterwards.
</Tip>

There is also a **New agent** dialog with ready-made templates if you would rather start from something already written.

## What makes it good

Everything the agent does comes from two things.

<CardGroup cols={2}>
  <Card title="Instructions" icon="pen-line">
    The job it owns, how to behave, and when to stop.
  </Card>
  <Card title="Tools" icon="wrench" href="/agents/tools">
    What it can actually reach. No tools means it can only talk.
  </Card>
</CardGroup>

Brief it like a capable new colleague. Say the goal and the edges, not every keystroke. The two that people forget:

- **When to stop.** What "done" looks like, and what it must never do.
- **When to ask.** Which calls it should hand back to a human instead of making itself.

## Make the output usable

By default an agent replies in prose, which is fine for a human but awkward for a flow. Define **output fields** and it returns structured data instead, so the next step can read `priority` or `customer_email` directly rather than parsing a paragraph.

That is what turns an agent from a chat window into something you can [run inside a flow](/agents/in-flows).

## Publish when it's ready

Agents have a **draft** and a **published** version, like flows. Tune the draft as much as you like without disturbing what's already running, then publish.

<Note>
Agents are capped at a number of steps per run, so a confused agent stops rather than looping forever. Raise the limit for genuinely long jobs.
</Note>
