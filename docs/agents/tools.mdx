An agent can only act through the tools you attach.

<CardGroup cols={2}>
  <Card title="Pieces" icon="puzzle-piece">
    Actions from your connected apps. Send the Slack message, create the CRM record.
  </Card>
  <Card title="Flows" icon="sitemap">
    Your own flows, as one tool. The agent decides *when*, the flow decides *how*.
  </Card>
  <Card title="MCP servers" icon="plug">
    External tools over [MCP](/mcp/overview), for systems that aren't pieces.
  </Card>
  <Card title="Knowledge bases" icon="book" href="/agents/knowledge">
    Files or [tables](/tables/overview) it can look things up in.
  </Card>
</CardGroup>

## Flows as tools

The most underused one. When part of a job must happen the same way every time, build it as a flow and hand it over.

## MCP servers

| | |
|---|---|
| **Transport** | Streamable HTTP, SSE, HTTP |
| **Auth** | None, access token, API key, custom headers |

Activepieces connects and lists the server's tools, so you confirm it works before the agent depends on it.

<Tip>
When an agent keeps getting something wrong, ask which of the four it was missing. Usually it needed somewhere to look something up, not a longer prompt.
</Tip>
