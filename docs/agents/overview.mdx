## Flow or agent?

Both can be built by describing what you want. The difference is **where the logic lives**.

|  | Flow | Agent |
|---|---|---|
| **The logic is** | Written down, once | Worked out each run |
| **Decisions come from** | Conditions you defined | The agent's judgement |
| **Same input twice** | Same steps, same order | May handle it differently |
| **Best when** | You know the procedure | The work varies case by case |
| **You steer it by** | Changing the steps | Changing instructions and tools |

A flow is predictable, which is what you want for anything that must happen the same way every time. An agent handles the cases you cannot write rules for in advance.

## What makes an agent powerful

One sentence of instruction can end up touching a dozen systems. The agent works out which ones and in what order, and you decide what it is allowed to reach.

And you keep the reins:

- **Pin any input.** Let the agent choose a value or set it yourself, field by field.
- **Cap the run.** A step budget stops a confused agent instead of letting it loop.
- **Shape the answer.** Output fields turn a paragraph into data the next step can use.
- **Limit who sees it.** Open it to the whole project or to a named few.
