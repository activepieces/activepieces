## What has changed?

#### Famulor 1.0.0 connects to the current workspace API

The Famulor piece moves from the legacy platform API to `https://app.famulor.io/api/v1`. Connections now need a current workspace API key from **Settings → API & MCP**. Resource IDs are UUIDs, action inputs follow the current OpenAPI contract, and responses retain the public `data`/`meta` structure. The piece requires Activepieces 0.92.0 or later.

The new piece provides a separate native action for each of the 425 public API operations, an optional guided **Run Workspace API Operation** action and 32 native polling triggers. Legacy campaign control becomes **Start Campaign** / **Stop Campaign**; legacy chat, WhatsApp-send and call-deletion actions must be rebuilt with the documented current messaging/history operations. Call, inbound-call and conversation-completion triggers now poll read-only endpoints instead of replacing assistant webhooks. New Campaign Lead and Conversation Completed skip records already present on enable and emit once per resource ID; re-adding a lead or reopening the same conversation does not emit again. Snapshot triggers for campaign statuses, campaign leads, bookings, callbacks and other resources emit the first observed occurrence per resource ID, skip matching records present on enable and scan the full result set. Scans reaching the 50,000-record limit fail without advancing state. Payloads are acknowledged when their flow run starts; native dedupe keys suppress overlapping submissions within the platform dedupe window. Use idempotent downstream writes when duplicate deliveries would matter.

#### What you need to do

Flows remain on the piece version they were built with until you upgrade. Before upgrading, reconnect with a workspace key carrying the required scopes, replace numeric IDs with workspace UUIDs, reconfigure step inputs and remap downstream fields from the current response. Check polling intervals and use test data before testing billable actions. Existing assistant/channel webhook destinations remain unchanged.
