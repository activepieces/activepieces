## Overview

Capabilities give the AI extra skills that the model can't do on its own, such as searching the web. You choose the service behind each one, once, for the whole platform. Builders don't need their own keys.

Go to **Platform admin** → **AI Center** → **Capabilities**.

![Capabilities page](/resources/screenshots/ai-center-capabilities.png)

<Note>
  Capabilities are available on Cloud and self-hosted Enterprise. Community Edition doesn't have this page.
</Note>

## The four capabilities

The page has two groups.

**Chat and agents**

| Capability | What it does | Works with |
| --- | --- | --- |
| **Web Search** | Searches the live web for current information. | A Tavily API key, or an AI provider key whose provider has built-in web search. |
| **Web Scraping** | Reads any web page as clean text, including JavaScript pages. | A Firecrawl or Apify API key. |
| **Image Generation** | Creates images, from photos to graphics with text. | A fal.ai API key, or an AI provider key plus the image model to use. |

**Knowledge bases**

| Capability | What it does | Works with |
| --- | --- | --- |
| **Embeddings** | Indexes knowledge-base files so agents can search them. | An AI provider key plus the embedding model to use, for example OpenAI, Google, Azure or OpenRouter. |

An AI provider key used for a capability must serve **all projects**. Add or edit keys on the [Providers](/admin-guide/guides/setup-ai-providers) page.

## What the card shows

The bottom of each card tells you where the capability stands:

- **Using** and a name: the capability is on. The name is the service or key it runs on, followed by the model when there is one.
- **Works with** and a list: nothing serves the capability yet. The list shows which keys can.

When you haven't set a capability up, it may still work through your chat key. Web search and image generation use the key behind your [Default chat model](/admin-guide/guides/setup-ai-providers#default-chat-model) when that provider supports them. Embeddings use the chat key when it supports embeddings, and otherwise your AI credits. In that case the card already shows **Using** with that key's name.

## Set up a capability

<Steps>
  <Step title="Open the card">
    Click **Set up** on the capability. If it is already in use, the button says **Change**.
  </Step>
  <Step title="Pick the source">
    When there is more than one option, pick it under **Source**: one of your AI provider keys or an outside service.
  </Step>
  <Step title="Enter the details">
    For an outside service, paste its API key. The dialog links to where you get one. For an AI provider key, pick the **Image model** or **Embedding model** when the capability needs one.
  </Step>
  <Step title="Save">
    Click **Save**.
  </Step>
</Steps>

If no key can serve **Embeddings**, the card shows **Connect a provider** instead. Add a key that serves all projects and supports embeddings first.

<Warning>
  Changing the Embeddings key or model doesn't re-index files. Files already in knowledge bases keep their old vectors. Re-upload them to search with the new key or model.
</Warning>

## Reset a capability

Hover the card and click the trash icon to **Reset** it. This removes the saved API key or key choice. The capability then goes back to your chat key, if that key supports it. Otherwise it turns off.

## Providers vs capabilities

**Providers** connect the AI models that chat, agents and AI steps run on. **Capabilities** add skills on top of those models: web search, web scraping, image generation and embeddings.
