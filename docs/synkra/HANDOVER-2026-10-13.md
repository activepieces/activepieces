## UPDATE 13 Oct 2026 — RESOLVED

### BUG 1 RESOLVED — Paystack env loading

**Root cause:** Every system property in Activepieces is read as
`AP_<PROP_NAME>`. Our custom vars were stored as `SYNKRA_PAYSTACK_SECRET_KEY`
which the app could never see. It was looking for
`AP_SYNKRA_PAYSTACK_SECRET_KEY`.

**Fix:** Prefixed all custom vars with `AP_`:
- `AP_SYNKRA_PAYSTACK_SECRET_KEY`
- `AP_SYNKRA_PAYSTACK_PUBLIC_KEY`
- `AP_SYNKRA_PAYSTACK_WEBHOOK_SECRET`
- `AP_SYNKRA_PAYSTACK_PLAN_STARTER`
- `AP_SYNKRA_PAYSTACK_PLAN_BUSINESS`
- `AP_SYNKRA_PAYSTACK_PLAN_PRO`
- `AP_RESEND_API_KEY`
- `AP_RESEND_FROM_EMAIL`
- `AP_RESEND_FROM_NAME`
- `AP_SYNKRA_AI_API_KEY`
- `AP_SYNKRA_AI_BASE_URL`
- `AP_SYNKRA_AI_MODEL`

**Logged:** `synkra billing: Paystack fully configured.`

**RULE FOR FUTURE:** any new env var read via `system.get(AppSystemProp.X)`
must be stored in `.env` as `AP_X`. Never as `X`.
