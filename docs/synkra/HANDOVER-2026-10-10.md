# PART 2 — THE CUSTOM PIECE RECIPE (MOST IMPORTANT)

This is the pattern. It works. We built 8 custom pieces in a session
using this exact sequence. Do not deviate.

## Why we're fast

- Every piece follows the same 15-step process
- Copy an existing piece, rename, edit — never start blank
- Build/bundle/pack/repack/register in one flow
- Ship in batches of 2-3 pieces per build
- Never rebuild for one piece

## The 15-step process

### 1. Scaffold the folder

    mkdir -p packages/pieces/community/NEW_PIECE/src/lib/{actions,triggers,common}

### 2. `package.json`

    {
      "name": "@synkra/piece-NEW_PIECE",
      "version": "0.1.0",
      "main": "./dist/src/index.js",
      "types": "./dist/src/index.d.ts",
      "scripts": {
        "build": "tsc -p tsconfig.lib.json && cp package.json dist/",
        "bundle": "node ../../../../dist/packages/cli/src/index.js pieces bundle",
        "lint": "eslint 'src/**/*.ts'"
      },
      "dependencies": {
        "@activepieces/pieces-common": "workspace:*",
        "@activepieces/pieces-framework": "workspace:*",
        "@activepieces/core-piece-types": "workspace:*",
        "@activepieces/core-utils": "workspace:*"
      },
      "devDependencies": { "tslib": "2.6.2" }
    }

### 3. `tsconfig.json` and `tsconfig.lib.json`

Copy from `packages/pieces/community/payfast/`.

### 4. `src/lib/auth.ts`

One of four types:
- `PieceAuth.CustomAuth` — most common (API key + secret pairs)
- `PieceAuth.SecretText` — single API key
- `PieceAuth.OAuth2` — OAuth flow (only for AP-native pieces we don't own)
- `Property` — for dropdowns, text, checkbox inputs

### 5. `src/lib/common/client.ts`

One function that wraps the HTTP call. Handles:
- Base URL (live vs sandbox)
- Auth headers
- Error handling
- Response typing

### 6. Actions — `src/lib/actions/*.action.ts`

Pattern:
    export const actionName = createAction({
      auth: pieceAuth,
      name: 'snake_case_name',
      displayName: 'Title Case',
      description: 'What it does',
      props: { /* user inputs */ },
      async run({ auth, propsValue }) {
        return yourClient.request({...});
      },
    });

### 7. Triggers — `src/lib/triggers/*.trigger.ts`

    export const trigger = createTrigger({
      auth: pieceAuth,
      name: 'trigger_name',
      displayName: 'Title',
      type: TriggerStrategy.WEBHOOK,
      props: {},
      sampleData: { /* example payload */ },
      async onEnable(context) { /* register webhook */ },
      async onDisable(context) { /* remove webhook */ },
      async run(context) { return [context.payload.body]; },
      async test(context) { return [/* sample */]; },
    });

### 8. `src/index.ts`

    import { createPiece, PieceCategory } from '@activepieces/pieces-framework';
    // ...imports
    export const pieceName = createPiece({
      displayName: 'Title',
      description: 'Description',
      minimumSupportedRelease: '0.92.0',
      logoUrl: 'https://res.cloudinary.com/dewvhnks3/image/upload/...',
      categories: [PieceCategory.COMMERCE, PieceCategory.PAYMENT_PROCESSING],
      auth: pieceAuth,
      authors: ['synkra'],
      actions: [/* ... */],
      triggers: [/* ... */],
    });

Valid PieceCategory values:
- COMMUNICATION
- CUSTOMER_SUPPORT
- COMMERCE
- PAYMENT_PROCESSING
- PRODUCTIVITY
- SALES_AND_MARKETING
- DEVELOPER_TOOLS
- FILES_AND_DOCUMENTS
- ARTIFICIAL_INTELLIGENCE
- FORMS_AND_SURVEYS
- HUMAN_RESOURCES
- CONTENT_AND_FILES
- OTHER

**Note:** `SUPPLY_CHAIN` doesn't exist. Use `COMMERCE + PRODUCTIVITY` for
courier/logistics pieces.

### 9. Build

    npx turbo run build --filter=@synkra/piece-NEW_PIECE --force

Fix any TS errors before proceeding.

### 10. Bundle

    npx tsx packages/cli/src/index.ts pieces bundle packages/pieces/community/NEW_PIECE

This writes the bundled code to `dist/`. Verify:

    ls -la packages/pieces/community/NEW_PIECE/dist/src/index.js

**If it's missing, the bundle silently failed.** Run again, or check for
errors in the piece's actions/triggers.

### 11. Pack

    cd packages/pieces/community/NEW_PIECE/dist && npm pack
    cd /root/synkra-flow

Produces `synkra-piece-NEW_PIECE-0.1.0.tgz`.

### 12. Repack (strip workspace deps)

    scripts/repack-piece.sh packages/pieces/community/NEW_PIECE/dist/synkra-piece-NEW_PIECE-0.1.0.tgz

**This is mandatory.** Without it, AP's installer fails with "workspace
dependency not found".

### 13. Copy to assets

    cp packages/pieces/community/NEW_PIECE/dist/synkra-piece-NEW_PIECE-0.1.0.tgz \
       packages/server/api/src/assets/synkra-pieces/

### 14. Register in BUNDLED_PIECES

Edit `packages/server/api/src/app/synkra/billing/bundled-pieces.service.ts`:

    {
      name: '@synkra/piece-NEW_PIECE',
      version: '0.1.0',
      file: 'synkra-piece-NEW_PIECE-0.1.0.tgz',
    },

### 15. Add to piece set + refresh lockfile

    docker exec synkra-flow-postgres psql -U postgres -d activepieces -c "
    UPDATE piece_set SET config = jsonb_set(
      config, '{pieces,exceptions}',
      (config->'pieces'->'exceptions')::jsonb || '[\"@synkra/piece-NEW_PIECE\"]'::jsonb
    ) WHERE \"isDefault\" = true;
    "

    bun install
    git add bun.lock && git commit -m "chore: refresh lockfile"

    git add -A
    git commit -m "feat: NEW_PIECE integration"
    # Now build

## Critical rules

1. **Never rebuild for one piece.** Stack 2-3, then build once.
2. **Always `bun install` after adding a piece.** Otherwise Docker build
   fails on `frozen-lockfile`.
3. **Always repack.** Workspace deps break install otherwise.
4. **Version bump if cache poisoned.** If a piece fails with
   "Cannot find module ... src/index.js", bump to 0.1.1. The engine caches
   by name@version.
5. **Test locally first.** `npx turbo run build --filter=@synkra/piece-X`
   catches 90% of issues before the Docker build.
6. **Paste-safe chunks.** Heredocs >100 lines get truncated. Split into
   chunks with unique EOF markers.
7. **No fabricated URLs.** Every logo URL must be real. Test with curl.

## Common errors and fixes

| Error | Fix |
|-------|-----|
| `Workspace dependency not found` | Run `scripts/repack-piece.sh` on the tgz |
| `Cannot find module ... src/index.js` | Bump version to 0.1.1, clear engine cache in container |
| `bun install --frozen-lockfile` fails | Run `bun install`, commit `bun.lock` |
| `SUPPLY_CHAIN does not exist` | Use `COMMERCE + PRODUCTIVITY` |
| Missing `dist/src/index.js` | Bundle step failed — rerun |
| Piece installs but no icon | URL returns 404 — verify with curl |
| Piece doesn't show in picker | Not added to `piece_set.config.exceptions` |
| Piece shows but Connect fails | OAuth app not seeded in `oauth_app` |

# PART 3 — THE STACKING BUILD METHODOLOGY

## The rule

    STACK → BUILD ONCE → STACK NEXT WHILE BUILDING → DEPLOY → SMOKE TEST → TAG

Never rebuild for a one-line change. Never sit idle waiting on a build.

## Batch naming

v12, v13, v14 … each = one build = one deploy = multiple commits.

If it fails: retry as `v15b`, `v26b`, etc.

## Build commands

Start:

    rm -f /tmp/vN-build.log /tmp/vN-build.done
    nohup bash -c 'docker build -t synkra-flow:latest -f Dockerfile . > /tmp/vN-build.log 2>&1; echo "EXIT:$?" > /tmp/vN-build.done' > /dev/null 2>&1 &

Watch:

    while pgrep -f "docker build.*synkra-flow" > /dev/null; do
      echo "$(date '+%H:%M:%S') building... $(tail -1 /tmp/vN-build.log | cut -c1-100)"
      sleep 60
    done
    cat /tmp/vN-build.done

Deploy:

    docker tag synkra-flow:latest synkra-flow:backup-post-vN
    docker compose -p synkraflow -f docker-compose.yml -f docker-compose.override.yml \
      up -d --force-recreate app worker
    sleep 45
    curl -sS -o /dev/null -w "app: %{http_code}\n" http://localhost:8199/

**Note:** `pull_policy: never` is baked into compose. No `--pull never` needed.

## Smoke test after every deploy

    docker ps --filter name=synkra-flow --format "table {{.Names}}\t{{.Status}}"
    curl -sS -o /dev/null -w "app: %{http_code}\n" http://localhost:8199/
    curl -sS http://localhost:8199/api/v1/synkra/health
    docker logs synkra-flow-app --since 60s 2>&1 | grep -iE "error|fail" | head -5

## Expected build times

- Cold (cache cleared): 8-12 min
- Warm: 3-5 min
- Longest layer: `bun install --frozen-lockfile` (2-4 min)

## Coolify auto-gc warning

Coolify untags `synkra-flow:latest` overnight. Fix installed:
- Cron at 03:00 re-tags it daily
- `pull_policy: never` in compose prevents pull attempts
- Deploy works even if tag is missing (uses local image)

# PART 5 — LOCKED DECISIONS

Never violate these.

## Product identity

1. Flow owns all third-party credentials (OAuth tokens, API keys)
2. Chat owns billing and credits
3. Chat users never need a Flow account for Chat-included features
4. Chat-triggered consumption comes from Chat plan credits, not a Flow subscription
5. The Flow name appears in OAuth consent. Chat educates users about it.
6. Chat must not be deliberately inconvenient to force Flow adoption
7. No unbounded resource costs. Every plan has caps.

## Pricing

- Free: R0, 500 executions, 0 AI credits
- Starter: R299, 15k executions, 1k AI credits
- Business: R599, 50k executions, 5k AI credits
- Pro: R999, 150k executions, 20k AI credits, BYOK allowed

Source of truth: `packages/core/shared/src/lib/synkra/plans.ts`

## AI credits

- 1 credit = 1,000 tokens (input + output, rounded up)
- Applies to chat, agents, AI pieces, image gen, audio, embeddings
- Enforced pre-flight (before AI call)
- Chat is blocked, agent runs are blocked, AI pieces are blocked (v27)
- BYOK: Pro only
