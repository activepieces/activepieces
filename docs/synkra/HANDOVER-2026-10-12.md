## 2. How to deploy (CRITICAL — compose no longer works)

The docker-compose deploy HANGS. Do NOT use it.
Use raw docker run instead. Exact commands:

    cd /root/synkra-flow

    # Build
    nohup bash -c 'docker build -t synkra-flow:latest -f Dockerfile . > /tmp/final.log 2>&1; echo "EXIT:$?" > /tmp/final.done' > /dev/null 2>&1 &
    while pgrep -f "docker build" >/dev/null; do sleep 60; done; cat /tmp/final.done

    # Deploy (only when EXIT:0)
    docker rm -f synkra-flow-app
    docker run -d --name synkra-flow-app \
      --network synkraflow \
      --env-file /root/synkra-flow/.env \
      -e AP_CONTAINER_TYPE=APP \
      -p 8199:80 \
      -l traefik.enable=true \
      -l traefik.docker.network=coolify \
      -l "traefik.http.routers.synkraflow.entrypoints=https" \
      -l "traefik.http.routers.synkraflow.rule=Host(\`flow.synkra.co.za\`) || Host(\`automations.synkra.co.za\`)" \
      -l traefik.http.routers.synkraflow.service=synkraflow \
      -l traefik.http.routers.synkraflow.tls=true \
      -l traefik.http.routers.synkraflow.tls.certresolver=letsencrypt \
      -l traefik.http.services.synkraflow.loadbalancer.server.port=80 \
      synkra-flow:latest
    docker network connect coolify synkra-flow-app

    # Wait for health, then verify in browser
    sleep 45
    curl -sS -o /dev/null -w "public: %{http_code}\n" https://flow.synkra.co.za/

Worker deploy (rarely needs redeploy):

    docker rm -f synkra-flow-worker
    docker run -d --name synkra-flow-worker \
      --network synkraflow \
      --env-file /root/synkra-flow/.env \
      -e AP_CONTAINER_TYPE=WORKER \
      synkra-flow:latest

Postgres and Redis stay running — do NOT touch them.

## 3. THE RULE YOU MUST FOLLOW

Before ANY code change is deployed, do this:

    1. Make the change.
    2. Run: cd packages/web && npx tsc -p tsconfig.json --noEmit 2>&1 | tail -20
       (no grep filter, look at everything)
    3. Run: cd packages/server/api && npx tsc -p tsconfig.app.json --noEmit 2>&1 | tail -20
    4. Commit.
    5. Build.
    6. Deploy.
    7. OPEN https://flow.synkra.co.za IN INCOGNITO AND CONFIRM IT LOADS.
    8. ONLY THEN move on to the next change.

If step 7 shows a white screen or an error, STOP. Fix that first.
Do not stack new work on top of a broken deploy.

Today we broke production FOUR TIMES because we skipped steps 2 and 7.

## 4. What broke today and why

Four separate bugs, all introduced by the same class of mistake:
importing or referencing things that were never actually available at
runtime.

### Bug 1: OnboardingRedirectGate is not defined
Commit 547e7d5e.
We used <OnboardingRedirectGate> in guards/index.tsx but only
imported DefaultRoute from the same file. TypeScript did not catch it
because our type check was filtered to `grep -E "agency|onboarding"`.
Fix: added the missing import.

### Bug 2: useLocation outside router
Commit 5c577a72.
OnboardingRedirectGate wrapped <RouterProvider> in ApRouter. But
useLocation must be called INSIDE <RouterProvider>. Calling it outside
crashed the entire tree.
Fix: removed the gate wrapper; moved the onboarding check inside
DefaultRoute.

### Bug 3: barrel import pulled builder graph
Commit 3d1e8987.
DefaultRoute imported from '@/features/synkra-onboarding' (the barrel).
That barrel re-exported builder-nudge.tsx, which imported
useBuilderStateContext from @/app/builder/builder-hooks. Loading that
at router init time crashed the module graph.
Fix: changed the import to '@/features/synkra-onboarding/hooks'
(specific file, not barrel).

### Bug 4: lazyWithRetry not imported
Commit 40d2cfff.
automations/index.tsx used lazyWithRetry but never imported it. Again
TypeScript missed it because we were filtering output.
Fix: added the import.

### Bug 5: AuthenticatedDefaultRoute deleted
Commit 40d2cfff.
When rewriting default-route.tsx to move the onboarding check inside,
the AuthenticatedDefaultRoute component definition was accidentally
removed. Two places still referenced it.
Fix: restored the component.

## 7. Known unresolved issues

1. Coolify auto-gc deletes our docker images overnight.
   Coolify's periodic cleanup does not recognize our stack as "in use"
   because we're deployed outside Coolify's tracking.
   Effect: image synkra-flow:latest gets removed; docker compose up
   fails; the only fix so far has been to rebuild.
   Not yet fixed. Consider adding synkra-flow to Coolify's exclusion
   list, or deploying through Coolify itself.

2. docker compose is unreliable.
   Sometimes hangs indefinitely on up -d --force-recreate app worker.
   Reason unknown. Raw docker run works. Stick with docker run.

3. Service worker / cache.
   Users on older sessions may see stale JS. Hard refresh (Ctrl+Shift+R)
   or incognito solves it.

4. No source maps in production builds.
   When JS crashes, we get minified stack traces. Adding source maps is
   a small win for debugging. Not urgent.

5. Server restart is pending (kernel update).
   Do this during a quiet window. It will restart Coolify and all apps.

6. S3 backups still parked.
   rclone and boto3 both hang on Z1 S3. Unresolved. The database has no
   automated backup. This is a real risk.
