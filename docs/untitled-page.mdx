## **What Does Memory Mean When a Flow Runs?**

Every time a flow runs, Activepieces gives it a fixed amount of working space called **memory**. Think of it like a kitchen counter: everything the flow is working on has to fit on the counter at the same time. If the counter gets too full, the flow stops.

Here's what your flow memory holds:

- **The trigger data:** The information that started the flow, like a new email, a form submission or a new row in a sheet
- **The result of every step**: Everything each step produces is kept until the flow finishes, so later steps can use it
- **Every round of a loop**: When a flow repeats the same steps for each item in a list, the results of every round are kept, not just the last one
- **Files**: PDFs, spreadsheets, images or CSV files the flow downloads, creates or changes
- **Code steps**: Any custom code in your flow and the data it works with

**_Memory is only used while the flow is running and is cleared when it finishes. It has nothing to do with how many flows you have or how much data is saved in your account._**

## **How Do You Know You've Hit the Limit?**

The run shows as failed in your run history, with this message:

**_"Run failed due to exceeding the memory limit of 1024 MB"_**

(1024 MB is the same as 1 GB, the amount of memory your flow had.)

Here’s how this message compares with two others that look similar but mean something different:

| **Message** | **What it means** | **Usual cause** |
| :-- | :-- | :-- |
| _…exceeding the memory limit…_ | The flow needed more working space than it had | Very large files, very long lists, loops with many rounds |
| _…exceeding the log size limit…_ | The flow produced too much information to save in its run history | Many steps or loop rounds each returning a lot of data |
| _Run exceeded … seconds…_ | The flow took too long to finish | Slow apps, very long loops |

See [**What to Do About the Other Two Messages**](https://app.mintlify.com/activepieces/activepieces/editor/ginikachukwu%2Fdraft-nov-5/&#x7E;/cfaaa836-06e3-46cb-9e16-746f708a3990#what-to-do-about-the-other-two-messages) for how to fix them.

## **Memory on Activepieces Cloud**

If you use Activepieces at [cloud.activepieces.com](http://cloud.activepieces.com), these limits apply to everyone and can't be changed:

| **Limit** | **Amount** | **What this means** |
| :-- | :-- | :-- |
| Memory per flow run | 1 GB | The total working space each flow gets every time it runs. |
| Usable memory after overhead | About 700 MB | Activepieces needs about 300 MB of that space just to run your flow, so about 700 MB is left for your data and files. |
| Maximum file size per step | 10 MB | The biggest single file one step can handle, roughly a 100-page PDF or a large spreadsheet. |
| Maximum run history size | 25 MB | The most information that can be saved about a single run, across all its steps, so you can review it later. |
| Maximum run time | 10 minutes | How long a flow can run before it's stopped. Time spent waiting, for example for an approval or a delay, doesn't count. |
| Maximum webhook size | 5 MB | The maximum data another app can send to start your flow through a webhook link. |
| Maximum Store value | 512 KB | The maximum size of things you can save in one entry with the Store piece, which is meant for small things like a date or an ID. |

**Good to know:** Every flow run gets its own memory. If one flow runs out, it doesn't affect your other flows.

If your flow needs more memory, you can fix it using the tips in [**How to Build Flows That Use Less Memory**.](https://app.mintlify.com/activepieces/activepieces/editor/ginikachukwu%2Fdraft-nov-5/&#x7E;/cfaaa836-06e3-46cb-9e16-746f708a3990#how-to-build-flows-that-use-less-memory)

## **Memory on Self-Hosted Enterprise**

If your company runs Activepieces on its own servers, your IT team controls how much memory flows get.

To understand how, it's important to know what a worker is.

### **What Is a Worker?**

A **worker** is the part of Activepieces that actually runs your flows.

When Activepieces runs on your company's own servers, it has two main parts:

| **Part** | **What it does** | **Example** |
| :-- | :-- | :-- |
| **The app** | The Activepieces software your company runs on its own servers. It's what you open in your browser (at your own web address) to build flows, see runs and manage settings. Behind the scenes, it also receives every request to run a flow. | The front desk of a restaurant, which takes the orders |
| **Workers** | Separate machines, also on your company's servers, that do the work of running each flow, step by step | The cooks in the kitchen, who prepare the orders |

When a flow is triggered, the app puts it in a waiting line (a list of flows waiting to run). The next free worker picks it up, runs it from start to finish, sends the result back to the app, and picks up the next one.

### **What a Worker Is Made Of**

- **Processing power (CPU):** How fast it can work through the steps of a flow.
- **Memory (RAM):** The working space it uses to hold a flow's data and files while running it.
- **The Activepieces worker program:** The software that knows how to run flows and connect to your apps.
- **A protected space for each flow (sandbox):** Each flow runs in its own sealed-off area inside the worker, so it can't see or interfere with other flows. Think of it as a separate cutting board for each order.

### **Important Things to Know About Workers**

- **They don't keep your data:** A worker only holds a flow's data while running it, then clears it. Your flows, runs and files are saved by the app, not the worker.
- **You can have many of them:** Need to run more flows at the same time? Add more workers.
- **Their size sets your memory limit:** The memory a worker has decides how much data and how many files your flows can handle at once.

Your memory limit depends on how your IT team has set up the workers, so it might be higher or lower than on Cloud. The number in the error message shows your actual limit.

### **What to Do If Your Flow Needs More Memory**

If your flow needs more memory, you can use either of these two ways:

1. Change the flow using the tips in [**How to Build Flows That Use Less Memory**](https://app.mintlify.com/activepieces/activepieces/editor/ginikachukwu%2Fdraft-nov-5/&#x7E;/cfaaa836-06e3-46cb-9e16-746f708a3990#how-to-build-flows-that-use-less-memory). This is usually the quickest fix.
2. Ask your IT team to give the workers more memory.

### **How to Check Memory Usage**

Go to **Platform Admin → Operations → Workers** to see each worker's status and how much processing power, memory and disk space it is using.

## **Memory When Activepieces Is Embedded in Another Product**

Some companies build Activepieces directly into their own product, so their customers can create flows without leaving it. This is called **embedding**.

Embedding changes where people see the flow builder, not how flows run. Flows built inside an embedded product use memory in exactly the same way as any other Activepieces flow.

### **For Companies That Embed Activepieces in Their Product**

You're responsible for the memory your users' flows have. They can't change any limits, so it's up to you to set things up well and help them when a flow runs out of memory.

#### **Your Limits Depend on How You Run Activepieces**

**If you use Activepieces Cloud:**

- Every flow your customers run gets the standard Cloud limits: **1 GB of memory per run** (about 700 MB of it usable), **10 MB per file** and **10 minutes per run**.
- These limits can't be raised. When a customer's flow runs out of memory, the fix is to change how the flow is built.

**If you host Activepieces on your own servers:**

Your IT team sets the limits. Because many customers share your setup, three decisions matter most:

- **One flow at a time on each worker:** Each customer’s flow gets its own space, so one customer’s heavy flow can’t make other customers’ flows fail. Like each cook handling one order at a time, with the whole counter to themselves.
- **Workers big enough for your heaviest customers, not your average one:** If some customers process large files or long lists, their flows need more memory. Plan for them.
- **Dedicated workers for your biggest or most important customers:** Their flows run on their own workers and never wait behind or compete with anyone else’s. Like giving a big client their own private kitchen.

> **For your IT team:** One flow at a time is set with `AP_WORKER_CONCURRENCY=1`. Dedicated workers are set up with worker groups. Full details are in the [Production Setup](https://app.mintlify.com/activepieces/activepieces/editor/ginikachukwu%2Fdraft-nov-5/&#x7E;/53b8406b-3342-48c0-89f0-cc52a27ef7f0) Section

#### **Help Your Customers Help Themselves**

- **Show them their run history:** So they can see when a flow fails and read the error message.
- **Share the tips in this guide:** (Or your own version written in your product's name), so they know what "memory limit exceeded" means and how to fix it.
- **Tell them who to contact:** Your customers can't reach Activepieces support directly, so make sure they know to come to you.

## **How to Build Flows That Use Less Memory**

These tips work on both Cloud and self-hosted. Most memory problems can be fixed by changing how the flow is built, without needing more memory.

### **1. Only Bring In the Data You Need**

Most memory problems start with a step that pulls in much more data than the flow actually uses.

- Use filters in the step (for example, "only today's orders" or "only unread emails").
- Set a limit on how many records a step returns, if the step has that option.
- Pick only the fields you need (for example, just name and email instead of the full customer record).

For example if you need just the lead name, do not pass in data from the entire row. Instead click the filter and select the specific data you want.

### **2.**  Work in Smaller Groups

Instead of handling 50,000 rows in one go:

- **Fetch fewer records at a time.** Click the step that fetches your data and look for a field like **Limit**, **Max Results** or **Page Size** (the name depends on the app). Set it to a smaller number, for example 200.
- **Run the flow on a schedule** (for example, every 15 minutes) and handle one group each time.

**Example:** In Google Sheets, use the **Get Next Rows** action and set **Group Size** to 200. It remembers where it stopped, so each run picks up the next 200 rows.

If a step has no limit field, use its filters to bring in less data (As shown in step )

### **3. Move Heavy Loop Work Into a Separate Flow**

A loop (a step that repeats the same actions for every item in a list) keeps the results of every round in memory until the flow finishes. Looping through thousands of items adds up quickly.

A better way:

1. Create a second flow that handles just one item. Start it with the **Callable Flow** trigger (a trigger that lets another flow start this one). Publish the flow and make sure it's turned on, or it won't appear in the list in step 2.
2. In your main flow, use the **Call Flow** action from the **Sub Flows** piece inside the loop to send each item to that second flow.
3. Each item is handled in its own run with its own memory, so your main flow stays light.

If your main flow needs a result back from the second flow, tick **Wait for Response** in the **Call Flow** action, and end the second flow with the **Return Response** action from the same piece. The main flow pauses while it waits.

![Wait For Response](/images/wait-for-response.png "Wait For Response")

The second flow is often called a **subflow**: a flow that's started by another flow.

### **4. Big CSV Files: Use "Stream CSV to Subflows"**

For large CSV files (spreadsheet files with thousands or millions of rows), use **Stream CSV to Subflows** from the **Sub Flows** piece.

It:

- Reads the file a little at a time instead of loading it all at once.
- Sends groups of rows to another flow to process.
- Uses very little memory, however big the file is.

![Stream Csv To Subbflows](/images/stream-csv-to-subbflows.png "Stream Csv To Subbflows")

### **5. Big Files: Use Actions That Pass Files Along in Chunks**

Some actions can move large files without loading the whole file into memory. They pass the file along a few megabytes at a time, a bit like water flowing through a pipe instead of filling a bucket.

This happens automatically when you use one of these actions:

| **App** | **Actions** |
| :-- | :-- |
| Amazon S3 | Upload File, Read File |
| Azure Blob Storage | Create Blob, Read Blob |
| Dropbox | Upload file, Download File |
| Google Drive | Upload file, Read File Content |
| Microsoft OneDrive | Upload file, Get File |
| Microsoft SharePoint | Upload File |
| FTP/SFTP | Upload File, Read File Content |

**Example:** Copying a 2 GB video from Google Drive to Dropbox works with these actions, even though it's bigger than the flow's memory.

**Self-hosted only:** This works best when your IT team stores files in S3 (cloud file storage).

### **6. Pass the File, Not What's Inside It**

When a step gives you a file, pass the file itself to the next step. Don't convert it into text first, because that can use several times more memory than the file itself.

### **7. Save Big Data in Tables, Not Store**

- **Store** (a piece for saving small values between runs) is for little things like a date, a counter or the ID of the last item processed.
- **Tables** (spreadsheet-like tables built into Activepieces) are for lists and records.

### **8. Keep Code Steps Small**

A **Code step** is a step where you or a developer write custom code.

To keep it light:

- Only send on the data the next steps actually need, not everything the code received.
- Avoid loading whole files or very long lists inside the code.

Code steps may have a smaller memory limit of their own (about 128 MB), so they can run out sooner than the rest of the flow.

### **9. Split Big Jobs Into Several Flows**

If one flow does several heavy jobs in a row (for example: export data, then clean it, then upload it, then send a report), split it into separate flows that hand off to each other. Each new flow starts with fresh memory.

## **What to Do When You See "Memory Limit Exceeded"**

1. Open the failed run and find the step where it stopped.
2. **Look at what that step and the steps before it produced.** Look for very long lists, big files or large blocks of text.
3. **Pick the fix that matches:**
   - A step brings in too much data → filter or limit it (tip 1).
   - A loop with many rounds → move the loop's work into a separate flow (tip 3).
   - A big CSV file → use Stream CSV to Subflows (tip 4).
   - A big file → use an action from tip 5 and pass the file, not its contents (tip 6).
   - A Code step → make it return and load less (tip 8).
4. **Test the flow again.**

**Still failing?**

- **Cloud:** Split the work into smaller flows. The limit can't be raised.
- **Self-hosted:** Send the failed run to your IT team. They can check whether the workers need more memory.

## **What to Do About the Other Two Messages**

### **"Run Failed Due to Output of Steps Exceeding the Log Size Limit…"**

**What it means:** Your flow ran, but it produced too much information to save in its run history (the record of what each step received and produced, which you open to review a run).

**The limit:**

- **Cloud:** 25 MB per run. This can't be changed.
- **Self-hosted:** 50 MB per run by default. Your IT team can change it with AP_MAX_FLOW_RUN_LOG_SIZE_MB (the most information that can be saved about one run, in MB).

**How to fix it:** The causes are almost the same as for memory, so most of the same tips work:

- **Bring in less data** (tip 1). Filter, set limits, and pick only the fields you need.
- **Move heavy loop work into a separate flow** (tip 3). Every round of a loop is saved in the run history. With a separate flow, each item gets its own run history instead of one huge one.
- **Pass the file, not what's inside it** (tip 6). The contents of a converted file take up a lot of space in the run history.
- **Keep Code steps small** (tip 8). Only return what the next steps need.
- **Split big jobs into several flows** (tip 9).

### **"Run Exceeded … Seconds, Try to Optimize Your Steps."**

**What it means:** The flow took too long and was stopped before it finished.

**The limit:**

- **Cloud:** 10 minutes per run. This can't be changed.
- **Self-hosted:** 10 minutes by default. Your IT team can change it with AP_FLOW_TIMEOUT_SECONDS (how long a flow can run before it's stopped, in seconds).
- Only time the flow is actually working counts. Time spent waiting, for example in a Delay step or for an approval, doesn't count.

**How to fix it:**

- **Handle fewer items per run.** Fetch records in pages and run the flow on a schedule, handling one group each time (tip 2).
- **Move loop work into a separate flow** (tip 3). Each item then runs in its own flow with its own 10 minutes. If you tick **Wait for Response** in the **Call Flow** action, the main flow pauses while it waits, and that waiting doesn't count toward its time limit.
- **Split big jobs into several flows** (tip 9). Each flow gets its own 10 minutes.
- **Look for slow steps.** Open the run and check how long each step took. The time is shown on each step. A slow step is often an app that responds slowly, or a step that fetches far more data than it needs.

## **Common Questions**

### **Is Memory the Same as Storage?**

No. Storage is what's saved in your account, like tables, files and run history. Memory is the temporary working space a flow uses while it runs, and it's cleared when the run ends.

### **If One Flow Runs Out of Memory, Will My Other Flows Break?**

On Cloud, no. Each run has its own memory. On self-hosted, the same is true when your IT team uses the recommended setup of one flow at a time per worker.

### **Will the Flow Try Again on Its Own?**

The run is marked as failed. Fix the flow first, then retry it. Retrying without changes usually fails the same way.

### **It Worked When I Tested It. Why Did It Fail Later?**

Tests usually use a small sample. Real data, like a full month of orders or a large email attachment, can be much bigger.

### **My File Is Smaller Than 1 GB. Why Did It Still Fail?**

Activepieces itself uses part of the memory (about 300 MB). Files can also take more space once they're opened or converted, for example a 100 MB spreadsheet turned into a list of rows.

### **What Happens If All the Workers Are Busy?**

New flows wait in line and start as soon as a worker is free. They aren't lost, just delayed. If this happens often, your IT team can add more workers.

### **Can I See How Much Memory My Flow Used?**

Not yet. On self-hosted installs, your IT team can see how much memory each worker is using.
