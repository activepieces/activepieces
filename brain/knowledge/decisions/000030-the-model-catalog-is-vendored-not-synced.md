# The model catalog is vendored, not synced

## Decision

Per-model metadata ships as a generated JSON file committed to the repo
(`packages/server/utils/src/model-catalog.generated.json`, ~215 KB, 695 models), regenerated by
`npm run sync-model-catalog` and by a weekly workflow that opens a PR when the data moves. Nothing
fetches model metadata at runtime. The source is [models.dev](https://models.dev) and only models.dev.

## Context

The model picker needed cost, context window, release date and capability flags — none of which exist
in the tree. Two sources cover it: models.dev (MIT, no key) and Artificial Analysis, the only place
Speed and Intelligence scores exist.

## Why

**Vendored over a sync job** because of the self-hosting rule: a runtime sync needs a key or egress or
both, breaks air-gapped installs, and needs boot-ordering and staleness-vs-cache logic — and it needs
a committed file as its offline fallback anyway. So the file is the part that must exist; the job is
optional and can be added later as pure addition. The cost is stale prices between regenerations,
which the weekly PR bounds.

**models.dev only** because their MIT licence grants redistribution outright. Artificial Analysis was
rejected on their own docs: free-tier use requires attribution *and* "for redistribution rights or
bespoke contract terms, contact the team" — and committing their numbers to a public repo is
redistribution, not display. That drops Speed and Intelligence from the picker. The fallback if
someone wants them later is a per-install `AP_ARTIFICIAL_ANALYSIS_API_KEY` fetched at runtime, where
each install is its own API consumer, at the cost of the zero-setup guarantee for those two fields.

## Consequences

Metadata costs zero runtime egress and works offline, but is only as fresh as the last regeneration.
Every field is optional, so unmatched models (Azure deployment names, CUSTOM, anything models.dev
does not carry) degrade to the plain `{ id, name }` row. Adding a provider means adding it to the
script's provider map and re-running — the runtime needs no change. The picker has a cost bar and hard
numbers, but no Speed or Intelligence bars.
